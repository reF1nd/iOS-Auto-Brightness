# iOS Auto Brightness

[![CI](https://github.com/reF1nd/iOS-Auto-Brightness/actions/workflows/ci.yml/badge.svg)](https://github.com/reF1nd/iOS-Auto-Brightness/actions/workflows/ci.yml)

支持 KernelSU、APatch、Magisk 的 Android 自动亮度模块，提供平滑调光和可跨重启保留的环境照度与用户亮度偏好。

从 [Releases](https://github.com/reF1nd/iOS-Auto-Brightness/releases) 下载模块；版本变更见 [更新日志](CHANGELOG.md)。项目名称描述调光体验目标，不表示使用或复现了 Apple 的原生算法。

## 功能

- 前置光感主导，后置较亮时提供有限补偿，结合稳定确认、平滑和回差调光；前置无效时可回退后置或已验证的备用来源。
- 参考固定亮度曲线与滑块 gamma 换算；多个偏好样本共同修正曲线，不把照度节点锁死。按用户、面板和光感来源隔离保存，重启后恢复。
- 距离遮挡时保持已有输出并暂停调光和学习；手动模式和系统保护生效时释放控制；自动模式熄屏停止写入，唤醒和短暂暂停后的恢复从可信实际背光渐变。
- 夜间曲线、低电量限亮和阳光增强，始终服从系统温控及亮度上限。
- 安装时热更新、配置热加载、学习数据导入导出、独立离线诊断和 WebUI。

后置辅助是独立扩展，不声称复刻厂商的私有融合算法或权重；闭源参考版只在前置无效时使用后置。实现细节见 [功能说明与对照](docs/PARITY.md)。

## 兼容范围

Android 12（API 31）及以上，不限制品牌、ROM 或分辨率。安装包包含 ARM64、ARMv7、x86_64 和 x86 核心，安装时按 ABI 选择；支持采用标准模块服务和 BusyBox 的 KernelSU、APatch、Magisk。WebUI 需要支持 `ksu.exec` 的宿主，Magisk 用户需另备兼容宿主。

兼容性取决于实际系统能力：直接背光输出需要确认主屏节点、系统 brightness 与 HAL backlight 的相同映射，以及可用的系统温控、限亮原因和亮度上下限。未满足时暂停输出并报告原因，保留诊断和配置功能。只控制默认主屏，物理屏幕切换时重新校准。详见 [兼容性说明](docs/COMPATIBILITY.md)。

真机验证目前仅覆盖小米 17 Pro Max / Android 17 HyperOS 4 / KernelSU。其他设备和系统尚未经过实测，自动测试通过不代表全部真机场景通过。

开发阶段曾在真机出现反复闪动，当前控制冲突修复仍需实机验收；Actions 自动检查结果与视觉验收分开，不能据成功构建认定闪烁已经解决。具体结果见 [验证记录](docs/VALIDATION.md)。

## 安装与更新

1. 在 [Releases](https://github.com/reF1nd/iOS-Auto-Brightness/releases) 下载模块 ZIP，可使用同名 `.sha256` 文件核对完整性。开发构建可从成功的 Actions 运行下载 `kernelsu-module` artifact，解开后安装内部 ZIP。
2. 使用 Root 管理器安装模块。首次安装需要重启；首次安装后尚未重启时再次安装，也仍需重启。
3. 已正常运行的模块支持安装时热更新：停止旧服务、替换文件、启动并检查新服务，安装器退出后清除本模块的待重启标记，WebUI 立即可用。启动失败会回滚；不满足热更新条件时保留正常的重启安装流程。
4. 开启系统自动亮度，通过 Root 管理器的 WebUI 入口查看状态与调整参数。

禁用模块后，后端与监督进程都会退出。重新启用后，可在 WebUI 点击“启动服务”恢复；此入口不依赖后端在线，也不会自动切换模块启用状态。首次安装尚未重启、待卸载、待完成更新或存在冲突模块时会拒绝启动并说明原因。

遇到确认的输出冲突或读写故障时，模块停止调光、恢复节点权限，并保存 `output-fault` 原因。监督重启、手机重启和热更新都不会自动清除；排查后需在 Root 管理器禁用模块、等待所有模块进程退出，再启用模块并点击 WebUI“启动服务”重新核验。短暂读数过渡或尚未完成的探测只暂停写入，不反复释放和重新接管。

手动启动和热更新会在创建服务前脱离管理器应用的 cgroup，避免管理器被回收时连带停止服务。无法确认脱离成功时拒绝启动；不会关闭系统的应用回收机制。

热更新不会清除其他模块的重启需求。事务备份和诊断位于私有数据目录的 `updates/`、`hot-update.log` 和 `update-status`。

## 学习与数据

环境光稳定时调节系统亮度条并松手，等待下一轮合格采样，在 WebUI 中确认调节事件以 `saved` 开头。控制与学习使用同一照度坐标，来源切换不会覆盖其他来源的记录。

当前参考流程读取 0～255 系统亮度设置，使用 `manual_gamma` 和固定表换算偏好。相邻采样至少间隔 8 秒，设置稳定至少 1.5 秒，且两次合格采样差值至少 10 格才记录；小变化不会逐轮累积成一次调节。初始读取、亮屏最初 8 秒、DIM、正在拖动及输出待确认期间不学习。该方式沿用原版的设置变化判断，仍无法在所有 ROM 上区分用户与系统改写，不宣称是真实触摸事件。非 0～255 的滑块报告不支持学习。所有学习均服从系统保护。

拟合以预设曲线为基准，所有样本按对数照度距离共同贡献偏差，并保留零偏移先验；在对数亮度空间合成偏差，对亮度加 0.005 底值后的比例限制为 ¼～4 倍，输出不低于基准的 ¼，纯黑也能学习上调，之后做单调投影，避免负偏移把暗处曲线压平到零。样本并非强制通过的锚点，界面表格显示观察值，曲线显示拟合结果。最多保存 32 个样本，相近照度合并。旧的全局偏移按其 ±0.3 范围映射到同一比例边界。

两侧有效时，后置较亮可贡献 25% 的对数照度差，限制 `(照度 + 1)` 最多为前置的三倍；后置更暗不会压低前置目标。明显的后置变化需稳定五秒，小变化交由平滑滤波处理。后置按变化上报的稳定读数继续保留，前置失效时可回退使用。新来源 `dual_weighted_v1` 与旧双侧取大、单侧学习文件隔离，旧文件原样保留，不自动套用。

WebUI 支持查看和清除样本、导入导出、参数调整及日志。在线保存由核心确认，离线配置保存通过同一个原生解析器校验，服务恢复后生效。

数据位于 `/data/adb/ios_auto_brightness/`，升级和卸载默认保留。首次安装可校验迁移闭源参考版的配置和单个偏移值，已有配置优先；不会生成虚构的历史学习点。新曲线样本使用独立的 `v68curve2` 身份与 `IAB_CURVE_OBSERVATIONS_V2` 格式，旧固定点文件保留但不自动迁入。

## 系统保护与已知限制

调光直接写主屏背光节点。普通外部改写只更新实际输出，模块曲线目标不变时不会重复追写；只有环境、偏好或策略使目标累计跨过原有滞回门槛，才从最新实际值开始新的渐变。环境处理以 800 毫秒为基准，EMA 按该周期归一化；已有渐变以约 50 毫秒推进，动画帧不作为新的环境变化反复启动滤波。普通升亮至少采用 800 毫秒渐变，并限制低亮度下的相对上升速度；长时间读取停顿不会在下一帧一次性追完动画。

自动模式接管时将节点权限设为 0444，退出恢复原权限，不修改节点所有者、系统亮度设置或持久系统属性。该权限无法撤销系统已打开的可写句柄，不等于独占。明确的滑块临时请求和超时 DIM 暂停写入并保留权限；松手后先完成稳定采样，再从现场亮度衔接，模块不重放系统 DIM 动画。普通自动亮度或 BCBC 的一致现场变化不会自动触发释放或永久故障，而是同步实际输出，禁止以旧高值直接续写。熄屏时停止写入；唤醒需有效读数，接管和恢复从实际背光渐变，退出不回写旧框架亮度。

写入前复核系统温控、限亮、应用覆盖及一致的节点/驱动读数。瞬态读数不一致或写入前再次变化只暂停该帧；请求与驱动回报持续不匹配至少 500 毫秒，以及真实 I/O 错误、量程或权限变化会锁存。温度不可用时禁止强光增强，不改动系统温控机制。厂商未公开的保护与跨进程竞态仍需按设备验证，不能保证任意 ROM 上直写都具有与系统显示链路等同的保护。

参考流程与闭源版一样不主动移动系统滑块；它通过滑块换算调整曲线，不保证滑块数值与实际背光比例相等。通用曲线、传感器识别与接口降级的边界见 [兼容性说明](docs/COMPATIBILITY.md)，实际测试范围见 [验证记录](docs/VALIDATION.md)。

## 构建与发布

编译、自动测试、静态检查和打包统一由 [GitHub Actions](https://github.com/reF1nd/iOS-Auto-Brightness/actions) 执行，包含核心与持久化回归、ASan/UBSan、Java、四种 ABI / DEX 编译、安装事务、WebUI 和 Android 12/15 模拟器检查。

Release 工作流复用完整 CI，校验标签、模块版本、安装包源码提交及 SHA-256 后上传附件。维护者操作见 [贡献约定](CONTRIBUTING.md)。

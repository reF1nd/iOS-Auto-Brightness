# v6.8 功能对照与当前实现

> 当前参考控制流程与多样本拟合见 COMPATIBILITY.md 文末，最新静态对照见本页“beta.23：重新核对背光写入链路”；本文件早期对临时亮度控制、固定学习点和不改节点权限的描述是历史记录。


依据：用户提供的闭源包配置、脚本、界面及本地静态行为分析。只重新实现功能，不分发或复制原二进制、网页资源。功能对应不代表逐指令或逐帧输出相同。

保留新版修正：连续基础曲线、目标设备标定、系统临时亮度控制、学习点原子持久化、用户隔离、AOD/唤醒处理。原作者头像、联系方式等不属于需要移植的调光功能。系统亮度条同步明确排除在本轮范围外。

验证执行位置为 GitHub Actions；只有通过实际运行和设备观察的项目才能记入 VALIDATION。sysfs/IIO 在当前目标手机缺少可用照度节点，其发现与解析由测试夹具覆盖，不能标成该手机真机回退成功。


## beta.7 再次对照后的补全

此前“缺口全部补齐”的表述范围过宽。此次增加：配置表单、范围滑块与原始文本实时双向同步；未保存参数及阳光模式曲线预览、坐标网格和离线示例；服务离线配置读取与原生校验保存；独立安装/进程/配置/系统状态诊断和离线卡片清空；无默认 Sensor 对象时唯一前置名称发现；quiet/back/battery 等表面温度名称覆盖及系统严重温控抑制。

保留有意差异：不把 SoC 45°C 当作皮肤过热；不绕过系统上限开启 HBM；不恢复原版无限启动失败重试；多点持久化学习和位置变化保护继续生效。通用设备适配、API 基线和明确降级规则见 [兼容性说明](COMPATIBILITY.md)。亮度条同步未纳入这次补全。

## beta.9：学习兼容性、稳定备用光感与背光监测

- 事件接口是否可用由实际调用结果决定，首次探测前不假报可用；运行错误立即降级、明确报告原因，每 30 秒重试。缺少 nits 校准但有可靠事件时，以最近事件确认调节意图，释放临时请求并等待框架归一化亮度稳定后保存；超过 3 秒的延迟事件不用于这种即时输出捕获。
- 新增 `settings_learning=0`，默认关闭。用户可一次开启持续兼容学习，不必每次开启 30 秒窗口。它为不提供事件、调用失败或接口可访问但不产生事件的 ROM 提供设置轮询回退；实际事件优先于尚未保存的推断候选。仅在有效、无遮挡、稳定光感及无系统保护的自动亮度状态下捕获；事件与设置候选都仍经核心校验。设置变化无法严格证明用户意图，因此明确标为可能误学的可选功能，不默认启用。开启后处理间隔最多 1 秒，以免漏掉调节；默认模式保留稳定期省电策略。
- dumpsys 的 on-change 稳定读数不再单凭事件超过 15 秒丢弃。新 dump 必须同时证明唯一名称/handle、lux 类型、on-change 模式和 HAL 活跃订阅；原始事件仍须来自当前注册周期。验证租约最多 15 秒，失去活跃证据或 dump 失败即撤销；连续上报传感器和未知格式仍使用严格新鲜度限制。订阅活跃并不能证明硬件绝无故障，本功能不声称具备这种诊断能力。
- WebUI 将框架报告亮度与只读背光节点请求值、驱动回报、最大值分开。多个背光节点逐一列出，不猜测主副屏，不把缺失值冒充零或物理测光结果。监测和日志自动刷新不依赖桥接在线。

保留边界：Android 12+ 与必要系统接口；系统亮度条同步不在本轮；不恢复直接写背光或绕过温控的旧实现。本节是实现说明，验证结果另记 VALIDATION。


## beta.12：双侧照度与距离抖动

重新核对 v6.8 二进制：原版在自动模式下前置读数小于零、后置启用且读数非负时才采用后置，并无模块内双侧融合。原版距离遮挡时跳过本轮直接背光写入、降低轮询频率；重写版此前立即清除系统临时亮度请求，是新增的交接行为，并非原版算法。

beta.12 将两侧有效照度的较大值用于滤波、曲线和事件时间学习，固定 `dual_max_v1` 来源避免较亮侧变化时切换记录。记录身份包含规则版本和两颗传感器名称/厂商，单侧旧记录不迁入不同照度坐标，也不删除。失去一侧后降级到有效单侧，显式 sysfs 选择保持原语义。原始前置仍独立参与下降冲突保护，避免融合掩盖较弱后置场景中的前置突降。稳定的前暗后亮不触发误保护；双侧真实变暗可以正常降低。

距离近信号出现即保持已有模块输出、冻结照度处理并禁止学习，600 毫秒后记为持续遮挡，仍保持输出而不交回系统；远信号稳定 300 毫秒后恢复。确认阶段按 100 毫秒处理，即使传感器不重复上报也会完成确认。无已有输出时不制造覆盖，用户调节保持期不被覆盖。温控、应用覆盖、熄屏、手动模式和更低系统上限优先。没有可保持的模块输出时不从系统亮度制造新覆盖；真正的系统保护退出不属于距离防抖，不延迟处理。


## beta.13：强光快速响应与连续增强

- 在有效、无遮挡、无系统阻止、温度/电量安全且无用户调节保持期的条件下，对输入照度的强光状态确认。双侧明确都亮需至少 250 毫秒，单侧/备用来源需至少 750 毫秒，且必须有两次间隔至少 250 毫秒的处理确认；失效、遮挡、系统保护或照度回落会撤销确认。稳定 on-change 读数可以作为持续证据，不要求重复硬件事件。
- 确认强光后上行照度不再等待普通尖峰过滤和低通滤波。唤醒两秒内允许提前接管，目标取计算值与系统当前输出的较大值，再服从系统上限；正常亮屏增亮使用 400 毫秒渐变。常规暗处唤醒仍等待两秒，手动调节保持期优先，桥接不会绕过现有的设置变化保护。
- `high_lux_min_pct` 改为两倍照度阈值处的强光下限。阈值处增益为零，从阈值到两倍阈值按照度线性增加增益与下限权重；默认 15,000 lux 不突升到 90%，30,000 lux 达到配置的完整增强。WebUI 标签与稳态预览同步更新，已有配置文件无需迁移。
- 退出仍要求平滑照度连续低于阈值的 70% 达到配置时长；回到回差带重置退出计时。退出后的下降使用较缓渐变并保留每秒约 20% 的相对下降上限。安全限亮立即裁剪，系统热状态直接让出控制。

这属于新版体验改进，不是逐帧复刻闭源版。性能数字是控制算法目标，不作为未实测设备的端到端时延保证。

## beta.23：重新核对背光写入链路

本轮以闭源 v6.8 的本地静态反汇编为证据，没有执行闭源程序，也没有据此宣称已完成实机逐帧复刻。下列地址为所分析 ARM64 二进制内的指令地址；参考 ZIP 和反汇编文件保持私有，不随仓库分发。

| 环节 | 闭源版确证 | 当前处理及有意差异 |
|---|---|---|
| 正常背光写入 | `0x5018–0x5024` 将新输出与进程缓存的上次输出比较，相等跳过；`0x505c/0x5098/0x50a0` 分别 open、write、close | 恢复“目标变化才写”；相同模块目标不因外部节点改写而追写。保留 app_process 所需的已打开 FD，但不把权限控制称为独占 |
| 权限 | 启动 `0x37f8` 依模式选择 0444/0644；切自动 `0x3d40`、切手动 `0x3e20`、退出 `0x5550` 更改权限 | 保存原权限并持久恢复，支持原本 0644/0664/0660；不照搬固定恢复为 0644，也不更改所有者 |
| 既有系统句柄 | 未发现关闭其他进程 FD 或截断所有系统写入通路的代码 | 系统持有可写 FD 仅证明 chmod 无法保证独占，不能单独证明某次闪动由其写入；不试图关闭系统 FD |
| 回读与异常 | 无 actual_brightness/MI 驱动回读及“失配后释放、两秒后重接管”状态机；原版对 write 返回缺乏验证 | 增加一致快照；瞬态保持，稳定 500 ms 失配或真实 I/O/权限/量程故障锁存暂停，一次释放，不自动重接管；不复制忽略写入失败的缺陷 |
| 主循环节奏 | `0x3c14–0x3c38` 限制轮询间隔；AUTO 默认及动画中为 800 ms，稳定阶段可为 1600/8000 ms（`0x5334`、`0x5374–0x5398`） | 环境处理和 EMA 以 800 ms 为基准，趋势不随动画帧重复增加；已有输出渐变以约 50 ms 推进，这是为实际平滑输出保留的实现差异 |
| 渐变常量 | `0x4f84–0x4fbc`、`0x5490–0x5508` 可确认 0/80/180/300/400 ms 及增亮约 ×0.7；原主循环并未按这些时长逐帧采样 | 保留分档含义，不能将闭源常量直接说成其实际帧间隔；首次及暂停恢复至少 400 ms，从 live 背光起步 |
| 熄屏、唤醒与 DIM | `0x4030–0x4110` 读取 bl_power 判断 ON/OFF，无 framework DIM 判定；物理 OFF→ON 通过 `0x4270–0x429c` 转入 `0x4444` 曲线计算及一次直接写入 | 熄屏不写；唤醒等可信读样后渐变。短暂探测等待不伪装为唤醒，不再重置并直接跳到曲线。普通 DIM/BCBC 不反复交接，但 DIM 禁止学习 |
| 0.5～2 lux 暗段 | `0x5e9c–0x5eb8` 为 `1 + log(lux)/log(2) × 2`，与相邻低照度段不连续 | 修正为经过 0.5 lux/1 nit、2 lux/3 nits 的连续对数段，不复制原分段缺陷 |
| 后置光感 | `0x4218–0x4240` 仅在前置无效且后置有效时回退；不是双侧取大 | 按用户明确要求保留两侧较亮值与后置持续确认，标为功能扩展，不声称是原版私有融合 |
| 滑块读取 | `0x3c7c–0x3cd8` 约每 8 秒读取设置并限为 0～255；`0x50bc–0x50cc` 比较相邻值差至少 10 格 | 恢复相邻、至少 8 秒采样语义，不累计细小变化；增加设置稳定 1500 ms 和唤醒/DIM/拖动/保护禁学 |
| 学习模型 | `0x50d0` 起 gamma/固定表换算，`0x51f8–0x5268` 更新并限制单个全局偏移 | 按用户要求保留多样本对整个预设曲线的有界修正与重启持久化，不把观察点作为必须穿过的锚点 |
| 清理和故障恢复 | 原版退出恢复节点权限；未发现当前的框架亮度恢复写入逻辑 | reference 新记录退出只恢复权限，不写旧框架目标；`output-fault` 跨监督/开机/热更新保留，需管理器禁用使全部进程退出，再启用并从 WebUI 显式启动才能恢复 |

显示探测另外区分可信结果、明确不安全和暂不可判定，以完成时刻衡量有效期；查询等待本身不释放，已接管后持续失去可信结果才锁存故障。保留系统温控/限亮、HDR、应用覆盖检查，不修改系统温控服务或节点。

beta.22 的 Actions 虽通过，真机仍出现瞬时大跨度闪动，停止后用户确认恢复正常。此次修复当前尚未通过新的 Actions 和真机验收；目标手机已卸载模块并处于新开机会话，本轮只读检查不算安装或视觉验收。验证结论只在有实际结果后更新 [VALIDATION](VALIDATION.md)，不能把上述对照表当成“闪烁已解决”的证明。

# 验证记录

## v8.0.0-beta.2

### 自动测试

- `brightness_map_tests`：屏幕亮度表；`getCurrentNit` 与系统默认锚点（30/600/5000/17000/72000 lux）及实测暗处拖动（7.9595 逻辑尼特 → 0.008644696）；暗处与室内的亮度条上下限；参数校验；线性与单调三次样条（与系统转储的切线一致）；系统曲线与 AOSP 表曲线。
- `nit_controller_tests`：默认锚点；实测暗处拖动后的锚点；段两端的加权移动与恢复；三段各一个拖动、同段替换；矛盾拖动的删除与单调保持；good curve；高照度拖动落在最后一个锚点；2000 次随机拖动后锚点仍单调且每段不超过一个；`learn.conf` 读写、拒绝其他默认锚点和旧格式；从设备的 `dumpsys` 段接管锚点。期望值由系统字节码逐步手算。
- `android_resources_tests`：按 `ResourceTypes.h` 布局构造的表与 APK：UTF-8/UTF-16 字符串池、数组、布尔、浮点、整数、紧凑条目、16 位与稀疏偏移、缺项、默认配置优先于限定配置、overlay 依次覆盖、压缩与损坏文件。
- `engine_tests`：v6.8 主循环场景改用系统曲线后仍成立；拖动后立即更新锚点、面板稳定前不写入、重启后由锚点决定亮度、三段学习、夜间系数、表曲线不学习、息屏后的 good curve 条件（30 分钟、6 分钟加 20 lux、关闭策略）。
- `daemon_end_to_end`：模拟 `dumpsys display`、`cmd`、`pm`：旧学习文件被忽略并接管系统已有的暗处拖动、曲线自检、主屏拖动被学习并写入 `learn.conf`、稳定后曲线经过拖动点、学习重置。
- 本地另用设备上的 `framework-ext-res.apk` 与 `MiuiFrameworkResOverlay.apk` 核对读取结果，与 `aapt2 dump resources` 一致（这两个文件不入库）。

## v8.0.0-beta.1

### 自动测试

- `curve_tests`：曲线与 v6.8 WebUI 中作者独立实现的双精度曲线对照，误差不超过 1 级；面板表逐点、0.5 lux 不连续段、亮度条换算。
- `engine_tests`：模拟手机运行主循环，覆盖启动、平滑公式、尖峰限幅、回差、大幅与小幅变化的写入时机、快速变暗、阳光模式与温度门槛、手动模式、熄屏与唤醒、接近遮挡、夜间与低电量、刷新节奏、拖动识别与稳定后记录（含夜间系数、渐变中、等待期间不写入、重启后生效）、后置接管与交还。
- `learning_tests`：多点学习经过每个点、暗处点只影响暗处、点之间不超出亮度条范围、邻近替换、冲突与超量淘汰、单调性、文件读写。
- `brightness_map_tests`：屏幕亮度表换算；HyperOS 亮度条换算与系统默认锚点的实际尼特（30/600/5000 lux）、暗处/室内/户外上下限、正反换算与随照度单调。
- `dual_sensor_tests`：环形缓冲加权、裁剪、防抖、阈值曲线，以及后置接管、短暂闪光、副屏光线、前置被遮挡等场景。
- `settings_tests`：ABX 编码夹具（字符串池、整数、空值、布尔）、截断文件、文本 XML、配置覆盖规则。
- `daemon_end_to_end`：真实二进制在模拟 sysfs 与设置文件上运行，检查 0444/0644 切换、照度变化后的写入、状态输出、单实例锁、学习重置、手动模式放权与退出恢复。
- 安装、启动、cgroup 脱离、热更新事务、日志工具与 WebUI 测试沿用并适配 v7 的用例。

### 真机

小米 17 Pro Max / Android 17 HyperOS 4 / KernelSU，2026-10-29：

- 不安装模块，直接运行本地 NDK 构建 30 秒：前置、后置、接近传感器经 NDK 就绪；ABX 设置读取正常（模式 1，亮度条 23）；15.3 lux 时写入曲线目标 1633；稳定后刷新间隔升到 8000 ms；`SIGTERM` 后进程退出，节点恢复 0644。
- 设备调研结论见 [DEVICE.md](DEVICE.md)。
- 完整模块安装、热更新与长时间观感对比尚待进行。

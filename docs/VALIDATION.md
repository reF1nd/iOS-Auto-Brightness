## 真机已确认

- 主屏及背屏分别识别，运行时主屏标定匹配；主光感、后置辅助光感、距离传感器、温度、电量、当前用户、模式及系统亮度上限可读取。
- 观察模式不写亮度；系统滑块操作产生真实的 BrightnessTracker 事件。
- 主动模式使用系统临时亮度请求，Display 0 的来源为 `temporary`，背屏无临时请求。未更改 sysfs 权限或持久系统属性。
- 实际滑块调节进入 `saved`，生成 0600 的学习文件及备份；用户反馈未观察到亮度被明显拉回。
- 强制结束原生核心后，桥接清除临时请求，系统自动亮度接回；新进程从磁盘读取同一学习点，报告 `loaded`。
- 强制结束桥接进程后，监督服务清除临时请求并自动重启，重新读取同一学习点。
- 切到手动模式后不再应用调光、注销传感器；恢复自动模式后保留学习记录。
- `ba96476` 的 Actions 安装包通过 KernelSU 安装，配置及学习文件保留；该包的最终服务也已在本次开机中启动并确认 `loaded`。

## 仍存在的界面同步限制

刚进入暗处时，系统亮度条与实际屏幕亮度可能不一致。模块使用临时亮度请求，系统设置值与实际输出可以不同；本轮没有实现系统亮度条同步，不能将其列为已修复。该现象与暗处样本被过滤、锁屏后偏好失效分别记录。

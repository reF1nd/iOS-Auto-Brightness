# 实现计划

v8 起放弃 v7 的 Java 桥接与自研调光算法，改为按闭源 v6.8 守护进程逐条还原。v7 在真机上反复出现闪烁、亮度条与实际亮度不符，根源是高频写入并与系统的背光写入竞争。

## 原则

1. 调光逻辑与 v6.8 一致：同样的曲线、平滑、回差、渐变、刷新节奏与写入时机，依据见 [PARITY.md](PARITY.md)。
2. 只在 v6.8 自身失效或用户明确要求时偏离，并逐项记录原因：ABX 设置读取、只学习真实拖动、HyperOS 双光感策略、启动回差修正。
3. 不额外加入温控或系统保护逻辑；温度只用于 v6.8 原有的阳光增强门槛。
4. 构建与测试由 GitHub Actions 完成；Actions 通过不代表真机验收，闪烁等视觉问题以实机观察为准。

## 结构

- `core/curve.*`：lux → nits → 背光级别。
- `core/engine.*`：v6.8 主循环，硬件访问通过 `Platform` 接口，便于用模拟手机测试。
- `core/dual_sensor.*`：HyperOS `DualSensorPolicy` 的照度选择。
- `core/settings_reader.*`：ABX 与文本 XML 设置读取。
- `core/daemon.cpp`：NDK 光感、背光、电量、温度、信号与状态输出。
- `module/`：监督进程、控制脚本、热更新事务、WebUI。

## 待办

- 在目标设备上安装完整模块，对比 v6.8 的实际观感，重点观察暗处、背对台灯、解锁与亮度条拖动。
- 其他品牌没有 `back_lux` 传感器时只用前置；若需要其他设备的后置光感，再按实际类型适配。

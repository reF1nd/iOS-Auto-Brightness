# 目标设备适配

初始读取日期：2026-10-15。设备由用户确认为小米 17 Pro Max，HyperOS OS4.0.2.0.XPBCNXM / Android 17（API 37），KernelSU。

## 硬件与接口

- 主屏 1200 × 2608；背屏 976 × 596。模块只向 Display 0 发出调光请求。
- 主屏 sysfs 最大背光 16383，存在独立的 panel1 背屏节点。新实现不写这些节点，也不修改节点权限。
- 主光线传感器：tcs3760 Ambient Light Sensor Non-wakeup；背侧辅助传感器为厂商 back_lux 类型。
- 系统设置存储为 ABX 二进制格式。旧核心按文本 XML 读取的路径不适用。
- 主屏亮度标定取自显示服务的 `mBacklight` / `mNits`，记录在 `module/profiles/altdb.profile`。这是一组设备标定数据，不是从闭源实现复制的代码。
- 设备代号在普通 shell 和 root 环境中可能不同；适配以主屏几何信息及运行时标定表吻合为前提，不以可被修改的 Build.DEVICE 判断。

## 控制与学习

桥接通过 SettingsProvider 的 root 外部客户端接口读取模式，通过 Android 显示服务读取当前亮度、系统亮度上限与应用覆盖状态，并使用临时亮度请求。退出、灭屏、手动模式、HDR 或应用覆盖时清除临时请求，不改写用户的自动亮度开关。

用户学习依赖系统 BrightnessTracker 生成的 BrightnessChangeEvent，按时间、当前用户、主屏 ID、照度样本时效/稳定性以及色彩/省电修正过滤。`isUserSetBrightness` 表示短期模型状态，不能单独当作“用户刚刚拖动”的标志；不会仅因系统亮度设置变化而学习。

当前桥接由 root 进程执行。若 ROM 不向它提供其他用户的事件，其他用户仍隔离存储且不误学习用户 0 的记录；不能把此限制当作多用户真机验收通过。

传感器注册失败时释放控制，短期无事件则重新注册请求初始值。暂不使用依赖 dumpsys 文本格式的运行期照度回退；启动校验标定表时才读取一次显示服务诊断。当前配置与设备接口约束优先于旧模块的宽松回退行为。

## 开发测试与回退

开发构建先在独立的临时目录中以 `--observe` 运行，此模式记录事件和学习但不修改显示亮度。主动控制测试需要停止旧模块及其监督服务，避免原版继续写背光。设备重启前不应将临时调试进程视为已安装的开机模块。

安装 v7 后通过 KernelSU 重启切换旧服务。模块卸载保留 `/data/adb/ios_auto_brightness/` 中的学习和配置，WebUI 可明确清除学习。需要完全清理时，先停止/卸载模块，再由用户删除该目录。
